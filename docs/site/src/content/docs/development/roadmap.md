当前仅保留 libtpu → bundles 计时、CPU 输出模拟、Virtual HBM 和原生 XProf。

## Bundle 语义覆盖

已支持标量值可确定的循环、分支、phi、spill/reload 和 DMA 操作数。继续补齐跳转延迟槽、运行时输入相关控制流、指令延迟、DMA 和 collective 同步协议。静态 bundle 数不等于实际执行次数；先覆盖语义，再拟合硬件参数。

## SparseCore 对齐

已支持 SCS/TEC dump、操作级实测校准、输入/消费者依赖、入口布尔分支选择和原生 XProf 轨道。待补齐内部指令、DMA/同步、启动与跨设备争用；缺少校准或无法解析的路径仍报告缺口。

## 虚拟时间驱动调度

将请求到达、主机提交和设备完成放入同一个逻辑时钟，让虚拟完成释放 decode 步骤并影响 admission / batching。不能只让后台计时器任意跳过时间。

验收应包含独立设备重叠、依赖约束、可重入回调、晚到请求，以及主机 CPU 延迟不改变相同场景的模型结果。

## 通信与内存

补充在线路由、链路共享、归约算术和端点 HBM 流量；扩大子组通信与重新分片覆盖。区分已分配字节、live bytes、逻辑流量和物理流量，完善别名感知的 KV 更新计数。

## 真实 TPU 校准

在有硬件或已有实验捕获后，从孤立 attention 开始，记录源码版本、形状、dtype、拓扑、预热与重复配置。用对应局部调用的真实设备区间校准参数，再在未参与拟合的形状和 serving 工作负载上验证。

CPU wall-clock 不能作为 TPU 观测值。只有可辨识的参数才能拟合，覆盖 compute-bound 内核并不能独立确定 HBM 带宽。
