title: 支持范围与限制
description: 区分能够执行、已验证以及具有完整成本估算的路径。
---

**能运行、数值正确、成本已覆盖是三件不同的事。** 当前模拟器主要验证执行路径，并提供带明确缺口的性能模型。

## 执行与存储

| 功能 | 当前范围 |
| --- | --- |
| 主机与设备 | 单主机；多主机分布式初始化不支持 |
| 张量并行 | 已验证 1/2/4/8 设备；虚拟执行要求单 replica |
| 默认存储 | 实际 CPU 分配，应控制模型和 cache 大小 |
| 虚拟存储 | 超过阈值的静态浮点数组使用标量存储；超过阈值的整数/bool 数组拒绝 |
| 动态 shape | 虚拟存储不支持 |
| tuple | 虚拟模式拒绝 HLO tuple 参数和嵌套 tuple 输出 |
| 主机读回与指针 | 虚拟张量不支持；小浮点输出也可能是占位值 |
| 重新分片 | 已验证编译路径；部分 `device_put` 路径会读回主机，对虚拟数组失败，见[具体示例](/guides/tensor-parallelism/#为什么-device_put-会尝试读回主机) |
| 复制与 bitcast | 支持本地设备复制；虚拟远程复制和 buffer bitcast 不支持 |
| 控制逻辑 | 支持整数控制；虚拟模式保守拒绝浮点转整数/bool，包括比较、argmax、采样 |
| 完整 serving | 已验证小模型框架集成；完整大模型 serving 尚未验证 |

普通执行器 donation 支持；部分外部导入、异步分配和显式 control-donation API 会拒绝，避免绕过生产者追踪。未知 custom-call 和具有外部副作用的 TPU 调用会报错。

## 内存模型

- 虚拟存储阈值不是进程内存上限；主机权重加载可能先分配完整数据。
- `memory_stats()` 是按设备跟踪的逻辑句柄统计，不是主机分配器统计。
- 别名可能重复计数，编译临时存储和部分异步分配未完整覆盖。
- 96 GiB 是诊断容量，不强制执行 HBM 容量上限。
- 尚未模拟完整的物理 HBM 分配、碎片、KV 别名占用或 cache 行为。

## 性能模型

当前在线模型覆盖普通二维 dot、部分逻辑内存操作、受支持的分片和通信，以及有有效声明的 Pallas 成本。

以下仍可能出现成本缺口：动态控制流、未知或不均匀分片、子组 collectives、缺少声明的 Pallas 内核、通用 resharding 和向量计算。未知节点保留依赖，不表示真实耗时为零。

在线 ring 和有向链路是合成模型，尚未复现真实物理路由、collective 的端点 HBM 争用或归约算术。离线模型可配置路由与保守端点 HBM 预留，仍不是按比例共享带宽的模型。

## 时间与结果

- 在线完成使用真实时间期限，CPU 执行与框架开销会影响观测耗时。
- 离线 replay 使用固定的捕获工作负载，不重新决定请求到达、调度或 batch。
- 虚拟时间尚未驱动在线 PJRT 完成与 serving 调度。
- 参数尚未经过真实 TPU 校准，不可直接将结果解释为生产吞吐或硬件延迟。
