title: 项目概览
description: 了解 sim-pjrt 的用途、执行语义和性能模型。
---

sim-pjrt 让 JAX 和经过验证的 SGLang-Jax 工作负载在没有 TPU 硬件、没有 `libtpu` 的环境中运行。插件向 JAX 注册 `tpu` 后端，由 XLA 的 CPU 运行时执行底层程序。

## 可以用它做什么

- 验证 PJRT 接入、异步缓冲区、donation 和整数控制流程。
- 在单主机上运行多个模拟设备，探索张量并行。
- 通过虚拟存储分离权重、KV cache 的逻辑形状与物理存储。
- 采集 XProf，观察主机提交、设备资源预留和通信。
- 对同一份工作负载做离线重放，比较成本与调度假设。

## 三种容易混淆的概念

| 概念 | 含义 |
| --- | --- |
| CPU 功能执行 | 负责实际缓冲区、整数计算、控制流和异步生命周期 |
| 在线性能模型 | 按计算、HBM 和通信资源预留时间，并据此延迟公开的就绪事件 |
| 离线虚拟重放 | 从已有捕获重建依赖，用独立的虚拟时钟计算固定工作负载的时间线 |

**虚拟存储**是另一个独立开关：它改变符合阈值条件的浮点张量的物理存储，不会自动将在线调度变成虚拟时间调度。

## 数值语义

默认模式下，浮点 dot 返回零；没有输出别名的 Pallas 调用返回零，有别名的输出保留输入内容。其他受支持的 HLO 操作继续在 CPU 上执行。依赖这些占位值的分支也会跟随占位值。

启用虚拟存储后，涉及虚拟张量的操作会使用占位结果。为了避免错误的控制决策，浮点值转整数或布尔值的路径被保守拒绝。

## 如何理解结果

设备名称和速率是模型配置。模拟器没有复现 TPU 编译器、物理拓扑或指令调度，当前参数未经真实硬件校准。SGLang 输出的端到端耗时仍受主机 CPU 和框架开销影响。
